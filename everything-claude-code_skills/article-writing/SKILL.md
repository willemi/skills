# 文章写作

撰写听起来像真人且有观点的长文内容，而非 LLM 将自己打磨成重复文本。

## 何时激活

- 起草博客文章、散文、发布文章、指南、教程或通讯问题
- 将笔记、转录稿或研究转化为精炼的文章
- 从示例中匹配现有的创始人、运营者或品牌声音
- 收紧已写成长文的架构、节奏和证据

## 核心规则

1. 以具体事物开头：制品、示例、输出、轶事、数字、截图或代码。
2. 在示例之后解释，而非之前。
3. 保持句子紧凑，除非源声音故意扩展。
4. 使用证据而非形容词。
5. 绝不编造事实、可信度或客户证据。

## 声音处理

如果用户想要特定声音，先运行 `brand-voice` 并重用其 `VOICE PROFILE`。
不要在此处重复第二次风格分析，除非用户明确要求。

如果没有提供声音参考，默认为锐利运营者声音：具体、无情、有用。

## 禁止模式

删除并重写以下任何内容：
- "在当今快速发展的格局中"
- "游戏改变者"、"前沿"、"革命性"
- 单独作为桥梁的"这就是为什么这很重要"
- 虚假的脆弱弧线
- 仅为增加参与度而添加的结尾问题
- 不推进论点的传记填充
- 延迟要点的通用 AI 开场白

## 写作流程

1. 明确受众和目的。
2. 构建严格的提纲，每部分一个任务。
3. 以证据、制品、冲突或示例开头。
4. 仅在下一句需要空间时扩展。
5. 删除任何听起来模板化、过度解释或自吹自擂的内容。

## 结构指导

### 技术指南

- 以读者能得到什么开头
- 在主要部分使用代码、命令、截图或具体输出
- 以可操作的收获结束，而非温和的总结

### 散文 / 观点

- 以张力、矛盾或具体观察开头
- 每部分保持一个论点线索
- 使观点对证据负责

### 通讯

- 第一屏做实际工作
- 不要在前面堆砌日记填充物
- 仅在改善扫描性时使用部分标签

## 质量门

交付前：
- 事实声明由提供的来源支持
- 通用 AI 过渡已删除
- 声音与提供的示例或商定的 `VOICE PROFILE` 匹配
- 每部分添加新内容
- 格式匹配预期媒介
