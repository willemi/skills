# Agent Harness 构建

当你需要改进 Agent 的规划、工具调用、错误恢复和收敛到完成的方式时，使用本技能。

## 核心模型

Agent 输出质量受以下因素约束：
1. 动作空间质量
2. 观察质量
3. 恢复质量
4. 上下文预算质量

## 动作空间设计

1. 使用稳定、明确的工具名称。
2. 保持输入模式优先且范围狭窄。
3. 返回确定性的输出结构。
4. 除非无法隔离，否则避免使用万能工具。

## 粒度规则

- 高风险操作（部署、迁移、权限）使用微工具。
- 常见的编辑/读取/搜索循环使用中等工具。
- 仅当往返开销是主要成本时使用宏工具。

## 观察设计

每个工具响应应包含：
- `status`：success|warning|error
- `summary`：一行结果摘要
- `next_actions`：可执行的后续操作
- `artifacts`：文件路径 / ID

## 错误恢复契约

对于每个错误路径，包含：
- 根因提示
- 安全重试指令
- 明确的停止条件

## 上下文预算

1. 保持系统提示最小且不变。
2. 将大型指导内容移入按需加载的技能中。
3. 优先使用文件引用而非内联长文档。
4. 在阶段边界处压缩，而非任意 token 阈值。

## 架构模式指导

- ReAct：适用于路径不确定的探索性任务。
- 函数调用：适用于结构化的确定性流程。
- 混合模式（推荐）：ReAct 规划 + 类型化工具执行。

## 基准测试

追踪：
- 完成率
- 每个任务的重试次数
- pass@1 和 pass@3
- 每个成功任务的成本

## 反模式

- 过多语义重叠的工具。
- 不透明的工具输出，没有恢复提示。
- 仅有错误输出，没有后续步骤。
- 上下文过载，充斥不相关的引用。
