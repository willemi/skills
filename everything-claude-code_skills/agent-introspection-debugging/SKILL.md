# Agent 内省调试

当 Agent 运行反复失败、消耗 token 却没有进展、循环使用相同工具或偏离预期任务时，使用本技能。

这是一个工作流技能，而非隐藏的运行时。它教 Agent 在升级给人类之前系统地自我调试。

## 何时激活

- 达到最大工具调用/循环限制失败
- 反复重试但没有前进进展
- 上下文增长或提示漂移导致输出质量下降
- 文件系统或环境状态与预期不符
- 工具故障可能通过诊断和较小的纠正操作来恢复

## 范围边界

在以下场景激活本技能：
- 在盲目重试之前捕获故障状态
- 诊断常见的 Agent 特定故障模式
- 应用受控的恢复操作
- 生成结构化的、人类可读的调试报告

不要将本技能用作以下场景的主要来源：
- 代码更改后的功能验证；请使用 `verification-loop`
- 当更窄范围的 ECC 技能已存在时的框架特定调试
- 当前 harness 无法自动执行的运行时承诺

## 四阶段循环

### 阶段 1：故障捕获

在尝试恢复之前，精确记录故障。

捕获：
- 错误类型、消息和堆栈跟踪（可用时）
- 最后有意义的工具调用序列
- Agent 试图做什么
- 当前上下文压力：重复的提示、过大的粘贴日志、重复的计划或失控的笔记
- 当前环境假设：cwd、分支、相关服务状态、预期文件

最小捕获模板：

```markdown
## 故障捕获
- 会话 / 任务：
- 进行中的目标：
- 错误：
- 最后成功的步骤：
- 最后失败的工具 / 命令：
- 观察到的重复模式：
- 需要验证的环境假设：
```

### 阶段 2：根因诊断

在更改任何内容之前，将故障匹配到已知模式。

| 模式 | 可能原因 | 检查方式 |
| --- | --- | --- |
| 最大工具调用 / 重复相同命令 | 循环或无退出的观察者路径 | 检查最近 N 次工具调用是否有重复 |
| 上下文溢出 / 推理退化 | 无限制的笔记、重复计划、过大的日志 | 检查最近的上下文是否有重复和低信号的大量内容 |
| `ECONNREFUSED` / 超时 | 服务不可用或端口错误 | 验证服务健康状态、URL 和端口假设 |
| `429` / 配额耗尽 | 重试风暴或缺少退避 | 计算重复调用次数并检查重试间隔 |
| 写入后文件丢失 / 过时的 diff | 竞态、错误的 cwd 或分支漂移 | 重新检查路径、cwd、git status 和实际文件存在性 |
| "修复"后测试仍然失败 | 错误的假设 | 隔离确切失败的测试并重新推导 bug |

诊断问题：
- 这是逻辑故障、状态故障、环境故障还是策略故障？
- Agent 是否丢失了真正的目标并开始优化错误的子任务？
- 故障是确定性的还是瞬态的？
- 能验证诊断的最小可逆操作是什么？

### 阶段 3：受控恢复

用能改变诊断表面的最小操作进行恢复。

安全恢复操作：
- 停止重复重试并重新陈述假设
- 修剪低信号上下文，只保留活跃目标、阻碍因素和证据
- 重新检查实际的文件系统 / 分支 / 进程状态
- 将任务缩小到一个失败的命令、一个文件或一个测试
- 从推测性推理切换到直接观察
- 当故障是高风险或被外部阻塞时升级给人类

不要声称不支持的自动修复操作，如"重置 Agent 状态"或"更新 harness 配置"，除非你确实在当前环境中通过真实工具执行了它们。

受控恢复检查清单：

```markdown
## 恢复操作
- 选择的诊断：
- 采取的最小操作：
- 为什么这是安全的：
- 什么证据能证明修复有效：
```

### 阶段 4：内省报告

以报告结束，使恢复对下一个 Agent 或人类可理解。

```markdown
## Agent 自调试报告
- 会话 / 任务：
- 故障：
- 根因：
- 恢复操作：
- 结果：成功 | 部分 | 阻塞
- Token / 时间消耗风险：
- 需要的后续操作：
- 稍后编码的预防性更改：
```

## 恢复启发式

按以下顺序优先使用这些干预措施：

1. 用一句话重新陈述真正的目标。
2. 验证世界状态而非信任记忆。
3. 缩小失败范围。
4. 运行一个区分性检查。
5. 只有在检查支持时才重试。

糟糕的模式：
- 用略微不同的措辞重试相同操作三次

良好的模式：
- 捕获故障
- 分类模式
- 运行一个直接检查
- 仅在检查支持时更改计划

## 与 ECC 集成

- 如果更改了代码，恢复后使用 `verification-loop`。
- 当故障模式值得转化为直觉或后续技能时，使用 `continuous-learning-v2`。
- 当问题不是技术故障而是决策模糊时，使用 `council`。
- 当故障来自冲突的本地状态或仓库漂移时，使用 `workspace-surface-audit`。

## 输出标准

当本技能激活时，不要仅以"我修好了"结束。

始终提供：
- 故障模式
- 根因假设
- 恢复操作
- 证明情况现在好转或仍然阻塞的证据
